# Правила работы в команде

## 1. Язык

- Общение в чате, коммиты и описания PR — на русском.
- Комментарии в коде — на русском.
- README.md и вся папка `docs/` (включая карту проекта) — на польском: их читает преподаватель.
- Имена файлов и папок — латиницей, без пробелов и польских букв (ą ć ę ł ń ó ś ź ż).

## 2. Кто за что отвечает

Роль — это ответственность за качество своей области, а не монополия на неё. Если карточка просрочена, её перераспределит тимлид другому учаснику (раздел 3).

- Что именно и где делает каждый, определяют карточки на доске. Правим только то, что указано в твоей карточке.
- В общих файлах (словарь, вопросы к клиенту) пишем только в своём разделе.
- В чужую папку заходим, только договорившись с владельцем. Структуру `docs/` и чужие файлы без договорённости не меняем.
- `blocks/` — независимые блоки (один блок — один или несколько файлов). Блок не требует правок в ядре: подключает его в ядро Arsenii. Эта связь в `contract/` не описывается.
- Изменения в `contract/` затрагивают всех: сначала обсуждаем в чате.

## 3. Дедлайны

Правило одинаково для всех, включая тимлида. Его цель в том, чтобы работа не застревала.

- У каждой карточки один владелец и дедлайн (поле «Дедлайн»). Задачи небольшие, на одну короткую сессию. Срок ставит тимлид, обычно 1–3 дня.
- Задача сдана в срок, если до конца дня дедлайна (23:59, время Варшавы) открыт PR и карточка стоит в «Do przeglądu».
- Задача выполнена, когда PR слит. Если после ревью нужны правки, на них даётся около одного дня.
- PR, который не соответствует результату из карточки (пустой, формальный, не проходит проверки), возвращается на доработку без продления срока.
- Если не успеваешь, напиши в общий чат или лично тимлиду до дедлайна. Если есть незаконченная работа, которую можно показать, написать можно и после дедлайна.
- Если есть личная причина, по которой ты какое-то время не можешь брать задачи, напиши тимлиду лично и сообщи, на какой срок. Вдаваться в подробности проблемы не обязательно. В этот период тимлид не раздаёт тебе задачи, а потом распределяет нагрузку так, чтобы всё компенсировать.
- Дедлайн прошёл, PR не открыт, и ты ничего не написал(а): карточка освобождается. Тимлид перераспределяет её между теми, кто уложился в срок, и перед этим спрашивает согласия человека, которому передаёт. Вместо этого он может написать в общий чат и пингануть тех, кто уложился: кто первым ответит, тот берёт. Если никто не может, тимлид делает задачу сам или снимает её с доски.
- Если PR открыт после дедлайна, но до переназначения, он рассматривается как обычно.
- Перераспределение — это смена владельца в той же карточке. Вклад по git остаётся за тем, кто сделал работу.

## 4. Ветки*

- `main` — всегда рабочая. Прямой push в неё запрещён настройками репозитория.
- Одна карточка на доске = одна короткая ветка. Название: `<задача>-<имя>`, например `slownik-daryna-m`.
- Как создать ветку в GitHub Desktop:
  1. Вверху выбираем ветку `main` и нажимаем «Fetch origin» / «Pull origin», чтобы получить свежую версию.
  2. «Current Branch» → «New Branch», вводим название по схеме выше, основой выбираем `main`.
  3. Нажимаем «Publish branch».
- Закончили задачу — открываем PR (раздел 6)
- Работать в чужой ветке нельзя.

**\* Тимлид не создает ветки или PR, работает и пушит беспосредственно на `main` без чужого рассмотрения**
## 5. Коммиты

- Маленькие и частые, один коммит — одно изменение.
- Сообщение (поле «Summary» в GitHub Desktop) коротко говорит, что сделано: «Добавил палитру блоков», а не «правки».
- Каждый участник коммитит со своего аккаунта.

## 6. Pull request

- Закончили задачу с доски — в GitHub Desktop нажимаем «Create Pull Request» (меню «Branch»). В описании 1–2 строки: что сделано, и `Closes #номер` карточки.
- Одобряет, мержит и удаляет ветку тимлид.
## 7. Доска задач

- Каждая задача — карточка с одним владельцем, конкретным результатом и дедлайном.
- Начали задачу — карточка идёт в «W trakcie», открыли PR — в «Do przeglądu».
- Перераспределение задачи — это смена владельца в той же карточке (раздел 3).

## 8. Чего нельзя

- \* Пушить напрямую в `main` (запрещено настройками). 
- \* Работать в `main` или в чужой ветке. 
- Трогать чужой файл без договорённости.
- Коммитить пароли, ключи и большие файлы.

**\* Тимлид исключение**
## 9. Если что-то сломалось

Не паникуем, пишем тимлиду. Git хранит всю историю, любое изменение можно откатить: откат делается через PR.
