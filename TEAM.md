# Правила работы в команде

## 1. Язык
- Общение, коммиты и описания PR — на русском.
- Комментарии в коде — на русском.
- README.md, karta-projektu.md и папка docs/ — на польском (их читает преподаватель).

## 2. Кто за что отвечает
| Папка                 | Ответственный     |
|-----------------------|-------------------|
| `karta-projektu.md`   | Arsenii Liapim    |
| `runtime/`            | Arsenii Liapin    |
| `contract/`           | Arsenii Liapin    |
| `editor/`             | Bekzigit Kuatbek  |
| `docs/`               | Daryna Melnyk     |
| `design/`             | Daryna Kotiash    |

Работаем только в своих папках чтобы избегать конфликтов

## 3. Ветки
- У каждого разработчика есть одна постоянная личная ветка для своего направления, на которой последовательно выполняются все зависимые задачи.
- Перед началом работы и в течение дня регулярно подтягивайте изменения из `main` в свою личную ветку, чтобы ваш код не отставал от общего прогресса проекта.
- Поскольку код в личной ветке постоянно меняется и дополняется, любые изменения общих импортов, функций или контрактов обязательно заранее согласуйте с командой в чате.
- Когда крупный логический этап работы полностью готов, стабилен и проверен, открывайте Pull Request из своей личной ветки в `main` для слияния.

## 4. Коммиты
- Маленькие и частые, один коммит — одно изменение.
- Сообщение коротко говорит, что сделано: «Добавил палитру блоков».

## 5. Pull request
- Задача готова — пушим ветку и открываем PR.
- В описании 1–2 строки: что сделано.
- Перед PR подтягиваем свежий `main` в свою ветку
- Свой PR не мержим. Мержит тимлид.

## 6. Чего не делаем
- Не пушим на прямую в `main`.
- Не мержим собственный PR.
- Не трогаем чужую папку без договорённости.

## 7. Если что-то сломалось
Не паникуем, пишем в тимлиду. Git хранит всю историю, любое изменение можно откатить.
