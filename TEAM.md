# Правила работы в команде

## 1. Язык
- Общение в чате, коммиты и описания PR — на русском.
- Комментарии в коде — на русском.
- README.md и вся папка `docs/` (включая карту проекта) — на польском: их читает преподаватель.

| `docs/` (включая `01-karta-projektu.md`) | Arsenii Liapin   |
| `README.md`                              | Arsenii Liapin   |

- Работаем только в своих папках, чтобы избегать конфликтов.
- В чужую папку заходим, только договорившись с владельцем.
- Изменения в `contract/` затрагивают всех: сначала обсуждаем в чате.

## 3. Ветки
- `main` — всегда рабочая. Прямой push в неё запрещён настройками репозитория.
- У каждой папки одна постоянная ветка с тем же именем:
  `docs`, `design`, `editor`, `interpreter`, `runner`, `contract`. Ветки не удаляются.
- Работаем в ветке своей папки и только в ней, никогда в `main`. Если отвечаешь за несколько папок — переключаешься между ветками.
- Если в одной ветке работают двое, перед каждым push делаем `git pull`.
- Перед началом работы и в течение дня подтягиваем `main` в свою ветку: `git pull origin main`.
- Переключаемся командой `git switch <ветка>` (не `git checkout`: имена веток совпадают с именами папок).
- Docs и design: работаем через веб-редактор GitHub. Сначала выбираем ветку своей папки, затем коммитим в неё.

## 4. Коммиты
- Маленькие и частые, один коммит — одно изменение.
- Сообщение коротко говорит, что сделано: «Добавил палитру блоков», а не «правки».
- Каждый участник коммитит со своего аккаунта.

## 5. Pull request
- Закончили задачу с доски — открываем PR из ветки своей папки в `main`.
- Если предыдущий PR из этой ветки ещё не слит, новая работа попадёт в него же. Это нормально.
- Задача большая — открываем draft PR заранее.
- В описании 1–2 строки: что сделано.
- Перед PR подтягиваем свежий `main` в свою ветку.
- Для merge нужно одобрение другого участника (GitHub не даст иначе). Одобряем, только посмотрев изменения.
- PR тимлида одобряет: `<имя>`.
- Ревьюер смотрит открытые PR в течение 1–2 дней.
- Мержит тимлид кнопкой «Create a merge commit» (не Squash).
- После merge сразу подтягиваем `main` в свою ветку.

## 6. Доска задач
- Каждая задача — карточка с одним владельцем и конкретным результатом.
- Открыли PR — карточка идёт в «Do przeglądu». Слили — в «Zrobione».

## 7. Чего нельзя
- Пушить напрямую в `main` (запрещено настройками).
- Нажимать «Delete branch» после merge: ветки папок живут постоянно.
- Трогать чужую папку без договорённости.
- Коммитить пароли, ключи и большие файлы.

## 8. Если что-то сломалось
Не паникуем, пишем тимлиду. Git хранит всю историю, любое изменение можно откатить: откат делается через PR.
