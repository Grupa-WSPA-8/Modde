# Правила работы в команде

## 1. Язык
- Общение в чате, коммиты и описания PR — на русском.
- Комментарии в коде — на русском.
- README.md и вся папка `docs/` (включая карту проекта) — на польском: их читает преподаватель.
- Имена файлов и папок — латиницей, без пробелов и польских букв (ą ć ę ł ń ó ś ź ż).

## 2.1. Кто за что отвечает (фаза 1: документация)
- Основная часть работы проходит в `docs/`. Кто, что и где делает, определяют карточки на доске.
- Правим только то, что указано в твоей карточке. В общих файлах (словарь, вопросы к клиенту) пишем только в своём разделе.
- Структуру `docs/` и чужие файлы без договорённости не меняем.

## 3.1. Ветки (фаза 1: документация)
- `main` всегда рабочая. Прямой push в неё запрещён настройками репозитория.
- Одна карточка на доске = одна короткая ветка. Название: `<задача>-<имя>`, например `slownik-daryna-m`.
- Как создать ветку в GitHub Desktop:
  1. Вверху выбираем ветку `main` и нажимаем «Fetch origin» / «Pull origin», чтобы получить свежую версию.
  2. «Current Branch» → «New Branch», вводим название по схеме выше, основой выбираем `main`.
  3. После первого коммита нажимаем «Publish branch».
- Закончили задачу — открываем PR (раздел 5). После merge ветку удаляем.
- Ветки папок (`editor`, `interpreter`, `runner`, `contract`, `design`) пока не трогаем. Переход на них объявляет тимлид, когда начнётся фаза имплементации.

## 3.2. Ветки (фаза 2: имплементация)
- `main` — всегда рабочая. Прямой push в неё запрещён настройками репозитория.
- У каждой папки одна постоянная ветка с тем же именем: `docs`, `design`, `editor`, `interpreter`, `runner`, `contract`. Ветки не удаляются.
- Работаем в ветке своей папки и только в ней, никогда в `main`. Если отвечаешь за несколько папок — переключаешься между ветками через «Current Branch».
- Перед началом работы и в течение дня подтягиваем `main` в свою ветку: меню «Branch» → «Update from main».

## 4. Коммиты
- Маленькие и частые, один коммит — одно изменение.
- Сообщение (поле «Summary» в GitHub Desktop) коротко говорит, что сделано: «Добавил палитру блоков», а не «правки».
- Каждый участник коммитит со своего аккаунта.

## 5. Pull request
- Закончили задачу с доски — в GitHub Desktop нажимаем «Create Pull Request» (меню «Branch»). В описании 1–2 строки: что сделано, и `Closes #номер` карточки.
- Перед PR подтягиваем свежий `main` в свою ветку («Branch» → «Update from main»).
- Одобряет и мержит тимлид.
- Фаза 1: после merge удаляем ветку (кнопка «Delete branch» на странице PR на GitHub, а локально «Branch» → «Delete»).
- Фаза 2: ветки не удаляем. Если предыдущий PR из ветки ещё не слит, новая работа попадёт в него же. После merge сразу подтягиваем `main` в свою ветку.

## 6. Доска задач
- Каждая задача — карточка с одним владельцем и конкретным результатом.
- Открыли PR — карточка идёт в «Do przeglądu». Слили — в «Zrobione».

## 7. Чего нельзя
- Пушить напрямую в `main` (запрещено настройками).
- Работать в `main` или в чужой ветке.
- Трогать чужой файл без договорённости.
- Фаза 2: удалять ветки папок.
- Коммитить пароли, ключи и большие файлы.

## 8. Если что-то сломалось
Не паникуем, пишем тимлиду. Git хранит всю историю, любое изменение можно откатить: откат делается через PR.
